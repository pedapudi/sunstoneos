# Finite GPU client and device adapter

This adapter runs the existing repeated fixed-compute client through normal CLOSE, parks its providers, reports the copied results and calls `platform_exit(0)`. It is intended for maintainers composing the common returning FreeRTOS platform. The supplied ELF is development-only and physically ineligible: it retains the earlier full single-core monitor/runtime objects, which do not implement the required return. Physical GPU firmware execution, computation, shutdown and ROM return remain unqualified.

`SUNSTONE_GPU_FINITE_RETURN=1` requires the supervised, single-core compute configuration. The existing authenticated GPU contract and session validators remain in use. The client waits for the real PMIC provider, runs two sequential jobs and copies both results before CLOSE. It waits for STOPPED before invoking the finite completion helper. The finite path creates no USB task and performs no native USB controller construction or operation. Its PMIC binding uses the same existing provider constructors as the shared USB binding.

Completion requires the normal GPU firmware/local-idle/reset/platform-OFF sequence, an empty GPU resource token, no delegated lease, firmware memory OFFLINE and disabled GPU interrupt delivery. The adapter suspends the GPU worker and asks the PMIC task to park outside its polling callback. It checks empty PMIC request slots, no rail borrows, no retained provider failure and unheld register/I2C mutexes. It waits within the admitted session deadline for distributor write propagation and disabled, nonpending, nonactive INT95. It then reports both sequence identities and all 64 owned output words, rechecks the stop conditions and enters a task critical section before `platform_exit(0)`.

Failure parks the client and retains memory and outstanding ownership. It cannot publish success or establish safe restoration. The common monitor must preserve that distinction on every exception, timeout and unexpected return. A software flag or expired deadline cannot establish physical quiescence.

Build and inspect the development adapter from the repository root:

```sh
python3 apps/gpu-finite/build.py --evidence ~/.cache/sunstoneos/evidence/gpu-finite-adapter-20261018
PYTHONDONTWRITEBYTECODE=1 ~/.cache/sunstoneos/venv/bin/python apps/gpu-finite/check.py --evidence ~/.cache/sunstoneos/evidence/gpu-finite-adapter-20261018
PYTHONDONTWRITEBYTECODE=1 ~/.cache/sunstoneos/venv/bin/python apps/gpu-finite/prerequisites.py --evidence ~/.cache/sunstoneos/evidence/gpu-finite-adapter-20261018
```

Accepted evidence is under `~/.cache/sunstoneos/evidence/gpu-finite-adapter-20261018/layout-correction/`. The build preserves filenames required by retained-section linker rules. The prerequisite generator rejects runtime/session objects placed in BSS. The build reuses 82 accepted driver/startup objects and their frozen source bindings, including the earlier monitor/runtime source. It compiles the client, finite helper and build identity. The manifest uses the unsupported execution profile `gpu-finite-adapter-development-v1` and explicitly sets `physical_eligible=false`; it is not an admission record. Eight linked cases execute the actual client and completion guard/report with modeled service replies, scheduling, PMIC parking, locks, interrupt state and mappings. They cover successful stop and retained CLOSE, token, PMIC, lock, IRQ and mapping failures. The corrected pending-IRQ case reaches the GIC pending read before deadline expiry. Existing GPU CLOSE, memory, arithmetic and provider evidence is reused.

The generated `integration-prerequisites.json` records exact ELF-derived retained, BSS, stack, monitor and pool bounds. It lists the authenticated EL3 interfaces and the retained runtime objects that must survive BSS clearing. The current contract still admits write-back memory at `0x48000000..0x78000000` and non-cacheable memory at `0x78000000..0x79000000`, including the complete existing translation scan. The fixed-compute producer allocates 134 write-back pages and 51 non-cacheable pages, totaling 740 KiB. Those counts do not narrow the admitted geometry or prove ownership; a different composition must recompute actual allocation addresses.

The coordinator owns the remaining common-platform work: preserve the complete 288-byte GPU contract and 592-byte session, authenticate their image/epoch/generation/lease/digests, retain the EL1 runtime copies, establish mappings and pool publication, and stop scheduling before restoring stacks or writable image memory. Final cache maintenance must cover the actual dirty image, device backing and translation tables while retaining the monitor's own state and stack until the final operation. Recompute all bounds after linking that composition. Initial RAM/master exclusion, supported settled power and clocks, initial GPU isolation and supervised recovery remain physical prerequisites. This adapter creates no board-test request.
