# Returning single-core GPU application

This composition is for maintainers reviewing the A733 single-core GPU return boundary. The normal CMake target links the current finite GPU client with an application-local monitor, exit shim and reset tail when `SUNSTONE_GPU_FINITE_RETURN=ON`. It preserves the authenticated 288-byte contract, 592-byte session, full 768 MiB write-back pool and 16 MiB non-cacheable pool. The image remains physically ineligible until the coordinator reviews architectural return and hardware admission. No physical GPU execution or ROM return is established by this evidence.

The client copies both job results, completes normal CLOSE, suspends the GPU worker and parks the PMIC task. Its existing completion guard checks ownership, locks, requests and INT95 before entering a task critical section. The replacement `platform_exit` runs at EL1t. It requires successful completion, five exact DEVICE parent leases and no additional pool consumers. It checks only accessible CCU, PCK and GIC registers after GPU power-off. Firmware, BIF, SLC, wrapper and reset observations come from successful native CLOSE; the shim performs no powered-off GPU-window reads.

The five parents are firmware WB at `0x48000000..0x48022000`, compute payload WB at `0x48030000..0x48088000`, compute tables WB at `0x48022000..0x4802e000`, firmware NC at `0x78000000..0x7802d000` and compute firmware NC at `0x7802d000..0x78033000`. Exact ledger slot, generation, owner, extent and pool geometry are checked. Firmware owner is 9; compute owner is 10. Allocation parents remain DEVICE-owned after CLOSE; the firmware memory adapter is OFFLINE. The DMA32 write-back pool aligns the payload to 64 KiB; first-fit allocation puts the tables in the preceding gap. The two pages at `0x4802e000..0x48030000` remain free. `return.h` defines this fixed profile once for the exact allocation guard and publication span. A retained, immutable 16-byte ELF object carries that span to the host producer; malformed or unrecognized metadata is refused. These intervals identify the fixed workload's allocated bytes and do not reduce authorization or host restoration of the complete admitted pools.

After device stop is established, EL1 masks exceptions and disarms its physical and virtual timers. It publishes a receipt in retained WB memory, then executes DC CVAC over the linked CPU-private interval and the 136-page WB span containing all 134 allocated pages and the two owned gap pages through its existing Nonsecure EL1 mappings. A monotonic counter read before each 4 KiB page, at most 64 lines, bounds the loop by a deadline capped by the admitted session. A stall or counter regression is detected within one page. Each counter read carries an ISB, so a per-line check would execute one ISB per line: in the linked normal case, EL1 cleanup executes 312 ISBs, against 19,595 with a check on every line. The NC parents require ordering rather than cache cleaning. A DSB completes publication. The assembly tail clears EL1 M/C/I without accessing a stack afterward, then issues SMC 0x733.

EL3 requires the actual EL1t caller profile, disabled EL1 M/C/I and a valid published receipt. It rechecks the protected admission, session digest, runtime copies, exact allocation ledger, finite stop state and accessible device-off predicates, including exact CORE6 policy and status zero. The shared PPU mapping, clock and ownership must remain valid through these reads. Exception ESR, ELR and FAR remain local; the exception entry does not overwrite dirty Nonsecure log bytes through an uncached Secure alias. EL3 restores the inherited interrupt configuration within the same bounded interval and publishes the copied output packet at `0x42000100`. Failures retain ownership in the original stop loop. No failure authorizes restoration or another device start.

EL3 performs no VA cache clean of Nonsecure data. With EL3 translation disabled, that operation would address Secure physical cache tags and could leave Nonsecure dirty lines unpublished. The final reset tail calls the existing set/way `clean_data_cache` helper to retire late EL1 stack stores in both security spaces, invalidates instructions and requests the existing RVBAR/RMR reset sequence. Monitor translation tables were constructed at cacheoff EL3; they are not claimed as dirty Nonsecure EL1 tables. Secondaries remain admitted OFF throughout. The coordinator must review this architectural sequence before execution.

The complete current build and exact commands are recorded under `~/.cache/sunstoneos/evidence/gpu-full-integration-20261024/merged/`. The CMake path adapts the current single-core monitor with `current-monitor.patch`, retaining the authenticated runtime contract and secondary-OFF copy. Only the generated platform source renames its old exit symbol. All application, provider and return objects rebuild from the same headers.

The 29 linked return cases cover nominal publication and every retained refusal, including changed generation/extent, CORE6 policy, status and dynamic-state refusal at EL1, and a CORE6 change after the SMC that only EL3 sees. A security-tagged cache model keeps dirty Nonsecure lines distinct from DRAM until Nonsecure EL1 CVAC. GPU completion, hardware register effects, cache behavior and reset outcome remain modeled.

`build.py`, `return-build.py` and `monitor.patch` preserve historical partial-object reconstruction. They do not build the current runtime. The earlier attempted image and its source bindings remain documented in [HOST.md](HOST.md#failed-physical-attempt-and-input-audit); its failure does not qualify or locate a failure in the new image.

Physical execution requires coordinator-owned identity and physical admission, complete pre-launch snapshots of every declared dirty range, authenticated session preparation, one bounded launch and restoration only after a verified return packet and ROM availability. The offline build creates no queue item. Timeout or retained failure requires supervised recovery and excludes automatic retry. Earlier shared-byte handoff results outside the `ns-publication` evidence directory are superseded: they did not model physical address security and cannot support publication correctness.
