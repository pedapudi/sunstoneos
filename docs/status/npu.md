# NPU

**Status: implemented.**

The NPU path is implemented: native model decoding, mappings, shared-provider startup, interrupt 97 service, runtime clients, resident EL0 queue, loader admission, run-time graph registration, thermal policy and opt-in internal clock gating of the idle NPU. Repeated start and stop reliability is unqualified. Hardware values these paths assert (GIC priority views, interrupt routes, CPU identity) are in [the A733 hardware facts](../hardware/a733-facts.md).

**Software evidence:** `checks/npu-idle.py`, no host check (production owner, queue and idle code with modeled devices and nine regression mutations), `checks/npu-idle-report.py`, no host check (evidence: npu-job-overhead-cost-breakdown), `checks/npu-mmu.c`, `checks/os-npu-service.c`.

**Board-qualified scope:** At 852 MHz and 800 mV on ports 3-1 and 3-3: finite startup (4.0 ms) and ShuffleNetV2 inference (2.91 ms doorbell to interrupt) with matching outputs, CLOSE, local stop and normal ROM return; the resident command queue (1,000 matched jobs at 10.25 µs p50); the combined image of four NPU jobs under eight CPU workers; the idle benchmark with baseline, control and clock-gating images (61,231 matching jobs each); 15 single-operation graphs, two layer-normalization graphs and shader graphs byte-equal to the SDK simulator; NPU MMU faults on unmapped descriptor and program addresses with recovery in about 32 ms; 31 resident slots at ring depth 64 with backpressure, run-time graph registration and a run-time tensor link; 18 compiled graphs resident from a runner input region; 31 graphs registered by the EL0 application at run time with no graph linked into the OS; the mimus encoder's 16 layers at 512 frames (768 jobs in 233.4 ms with exact outputs, two step jobs in flight, one tensor link per layer, 96 graphs registered from a runner input region); mimus recognition of 20.46 s of speech with the 16 layers on the NPU at 852 MHz and 800 mV (compute 422.8 ms against 599.4 ms on the CPU, text, formatted text and feature checksum equal to the CPU's, and log-probability checksum equal to the host simulator chain's); the failure return of an application that fails with its NPU queue open, with the NPU report published and stopped. Repeated transitions are not qualified.

## Open work

1. Call the idle power owner from the OS NPU service (`npu_runtime_queue_power_start` is not called by the operating system image), then repeat the idle benchmark there. Qualify shared SRAM access while the clocks are gated and recovery from a fault while suspended.
2. Measure energy and the break-even idle time. The PMIC provider exposes no DCDC2 current or power readback, so idle savings need an external meter.
3. Qualify the combined image repeatedly and across both models: the active-cancellation image, and a 20-cycle start, inference, CLOSE and local-stop image. Qualify repeated start and stop.
4. Qualify the EL0 queue with the public-ring predicate in the power owner, and the saved generic sequence registration and returning diagnostic (`npu-el0-next-1101`). Repeat the add queue image with the clock record, so its figure is measured and not only granted.
5. Run larger command windows with the smaller doorbell word. A reservation that includes run-time graphs uses 512 KiB per command allocation; the manifest could declare a command size to shrink it.
6. Add exact per-job deadline interrupts through the scheduler's deadline facility (`kernel/scheduler/deadline.h`); do not add a device timer.
7. Run the `restart-*` cases of no host check on a restart image; the other cases pass.
8. Confirm on the board where the remaining layout time of admission goes. For the encoder's 96 graphs (14.5 MB) at 494 MHz on an A55, preparing the runtime takes 69.4 ms: copy 11.3 ms, decode 6.2 ms, layout 37.9 ms, native setup 13.3 ms. The container checksum runs with the Armv8 `CRC32` instructions, one aligned load for each eight bytes, and should take about 14 ms. A second timed pass over the same graphs on the board would confirm how the layout time divides between the operation inspection and the rest.
9. Derive the secondary cores' startup wait from the declared graph bytes and the measured preparation rate. The wait is a fixed 1 s: the launchers set the startup deadline to the start plus one second, and the admission rule in `platform/a733-smp-cached/admission.c` refuses a deadline more than one second ahead, inside the 4 s watchdog lease. Preparation of the encoder's graphs uses 69 ms of it.
10. Run recognition on the NPU on the board at 90 frames and above 512 frames (the simulator gives the CPU's transcript at 90, 300 and 1024 frames), and in sessions that repeat recognition or use live capture, the radio or the headset. The encoder task closes its queue only in the session that ends after one recognition, and the admission refuses live audio, radio and headset sessions that grant the NPU queue.
11. Bring the subsampling tile below 14.7 ms. The tile time follows its DRAM traffic (31 MB in 17.1 ms for the model's form, 22.2 MB in 14.7 ms for the board form) more than the compiler's cycles (1.24 and 1.62 board cycles per estimated cycle). conv2 is now most of it: 4.6 million estimated cycles, 9.4 MB read for a 3.6 MB input. The compiler refuses 8-bit weights for a convolution with a 16-bit input. Then qualify the timing on the board.
12. Run the NPU admission layout after the CPU clock is raised, if the startup time is ever worth it. Admission runs at the 494 MHz boot clock because the raise needs the scheduler (the PMIC owner task and a thermal reading) and admission must finish before any task exists (its trimmed reservation and queue tables go into the application's address space).
    Moving the layout and trim after the scheduler means building the application's NPU mappings later. At 1794 MHz the recognition's 83.6 ms of preparation would take an estimated 23 to 26 ms, if the CPU-bound parts scale with the clock and the graph copy is partly memory-bound.
    Deferred on 2026-11-12: about 60 ms, once per start.
13. Find why the shader operations of layer 0's entry graph take 136 µs each. Run `1794511367819209028-d215a2d7` timed every operation by running each graph's first k operations (build option `SUNSTONE_NPU_OP_TIMING`, measurement only): entry's 309 µs excess over the compiler's estimate is its two shader operations, 46 and 48, which move under 10 kB each; its 43 estimated operations take 473 µs against 457 µs. In step's stream-processor run from operation 38 to 55 the measured time falls one operation later than the estimate, so only pairs of those operations are meaningful.
14. Make subsampling's shader mask multiply faster or replace it. It takes 9.36 ms of the 14.6 ms job (run `1794511367819209028-d215a2d7`): 0.23 int16 elements a cycle over 1.81 M elements, moving 5.8 MB at 0.73 bytes a cycle, so memory does not limit it. Its convolutions run faster than the compiler estimates: the 3 by 3 convolution takes 3.60 ms at 931 MACs a cycle (estimated 622, peak 1,536), the first convolution 0.56 ms against 1.27 ms. Run `1794508867203238346-402089f4` ruled out NPU MMU page size (1 MiB and 64 KiB pages save 0.3%). The page-size build (`SUNSTONE_NPU_TENSOR_PAGE_SHIFTS`) and the traffic counters (`SUNSTONE_NPU_TRAFFIC_COUNTERS`, 12.8 bytes a count) stay build options.
