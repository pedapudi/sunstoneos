# Partitioned scheduler integration

**Status: implemented.**

The partitioned fork is the default kernel in SMP images, and `-DSUNSTONE_PARTITIONED_SCHEDULER=OFF` builds the global FIFO-lock kernel as a control. The design is [the scheduler design](../designs/scheduler-partitioned.md); the priority map and tick are in [the scheduler timekeeping design](../designs/scheduler-realtime.md); hardware values that the interrupt and mask paths assert (GIC priority views, routes, CPU identity) are in [the A733 hardware facts](../hardware/a733-facts.md). The lock status is in [FIFO kernel locks](scheduler-locks.md), the timing budgets in [latency](latency.md) and the topology queries in [CPU topology](cpu-topology.md).

The cached-walk latency diagnostic measures A55 self-selection at 3 to 15.792 µs, control bodies at 3.125 to 20.375 µs and task-lock wait at up to 9.792 µs. Its instrumented CPU0 tick reaches 165.917 µs and busy task wake reaches 210.417 µs. The tick and wake path remain open. [The measurement record](../evidence/scheduler-latency-measurement.jsonl), entry `1794497365941804086-44d410dc`, defines the PMU windows and observer costs; these figures do not qualify the production task-wake percentile.

**Software evidence:** host, emulator, source.

**Board-qualified scope:** CPU-return images on port 3-3 run the recorded mimus recognition (eight workers, engine `bcaf39ff5`, output exact) with the OS services and drivers linked. The fork, the control interrupts above the kernel API mask (1, 2, 4, 8 and 10 kHz, one rate per core), the unmasked task-lock wait and idle pull return normally with exact output in 25 s soaks and single runs. The control path meets the 10 microsecond wake target at 10 kHz over 1 254 587 periods (maximum 3.6, 99.99th percentile 3.0 microseconds); the task path does not (maximum 23.5 to 31.5 microseconds at 1, 2 and 4 kHz). Figures are maxima of finite runs; they establish no worst-case bound, sustained operation, power behavior, heterogeneous placement or tickless timing.

## Known limits

- **Idle pull is on in the default fork** and every fork figure was measured with it on. A missed pull is a performance defect only: it cannot lose or duplicate a task, move a pinned task or invert priority. The cost of a miss is unmeasured. The eight-core check's stranding phase fails on the wall clock about 1 run in 50 at host load 30 and in none of 43 runs on the instruction counter.
- **Unmasked task-lock wait.** An EL0 task cannot read the mask, so the wait infers an open mask from a zero critical nesting count. A bare `portSET_INTERRUPT_MASK` outside a critical section can wait with the mask raised for at most 100 µs. The limit is checked only when an event wakes the core, so a wait behind a long holder can last as long as the holder (914 µs once).
- **Panic fixed.** One fork soak panicked before the exit guard existed (`1793608348858278119-8f8e4282`). A QEMU case reproduces it, and the fixed image ran 16 clean soaks. Board hours with control interrupts stay a watched item.
- Heterogeneous placement and tickless timing have no physical qualification.

## Per-object locks

Queues, event groups and stream buffers lock their own hashed slot instead of the two global locks. The object model verifies that unrelated slots do not wait for each other. Board comparisons establish no task-path latency improvement from these locks. Driver critical sections and scheduler compatibility sections retain global exclusion; the [locking design](../designs/scheduler-partitioned.md#sections-that-keep-the-global-locks) defines their scope.

Its eight periodic fixture notification targets remain legitimate load. Production task wake still needs qualification against the 10 µs 99.99th-percentile target. One maintenance entry attempts at most sixteen distinct records; its full physical batch cost remains unqualified. The unlock event must precede lifetime callbacks, so it cannot be deferred across records. A second event is emitted only when those callbacks run.

10. Move the control-interrupt measurement off PPI30 the next time it is needed. It uses PPI30 on CPUs 1-7, so its builds keep CPU0's periodic release and do not measure the shipped timer path.
11. After per-core precise deadlines (stage 7), revisit the woken-frame prefetch (stage 6c, work/sched-stage6-1114). Over three runs it lowered the mean busy wake on every one of CPUs 1-7 and CPU4's and CPU6's worst by about 4 µs, but at a cold wake 0 on CPUs 1-3 it added about 2,200 cycles of interrupt-exit work, which put the whole-phase worst over stage 5's on CPU1 and CPU3. 12. Explain the A76 cost of a per-core port line before trying it again (work/false-share-1115, 0cd0772ea). The SMP port keeps each core's critical nesting depth, ISR yield flag and interrupt nesting depth in three arrays of eight words. In the latency image the arrays are not line-aligned and span four 64-byte lines that every core writes, two of them shared with boot-only flags and a cause-bench word. The change moved the three words into each core's own `xPortCoreStates` line. Six interleaved runs on 3-1, three of the latency bar image without the change (8c0f8b89) and three with it (6e1300d1), both with `configSS_IRQ_SAVES_FP` 0:
    - On CPUs 1-5, the change lowered the mean busy wake by 0.7-3.0 µs and kept the three-run worst within the bar (the unchanged image's worst plus 1 µs).
    - On the A76 cores it missed the bar: CPU6 23.6 against 23.2 µs, CPU7 21.3 against 20.8 µs. CPU7's mean rose by about 1.1 µs in each of the three runs.
    - The 64-byte layout does not explain the A76 result. In the changed image each core's state is its own aligned line, with no other object in it and the new words at offsets 24-47. CPU7's line is followed by the first `xPortLocks` line in both images.
    - Two differences remain untested. The repository holds no A76 reference for either:
      - Pairing of 128-byte-aligned lines: without the change, CPU6's and CPU7's lines form one aligned pair. With it, CPU7's line pairs with the interrupt lock's line and CPU6's with CPU5's.
      - Code placement: the IRQ handler is 11 instructions shorter, which moves every later function.
