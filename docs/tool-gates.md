# Host execution gates and retained safety

This audit covers host-side Python and C under `tools/` and `apps/`. It compares the original candidate inventory at Git revision `6e082403` with the integrated cleanup. Process records no longer serve as execution permission in the changed, unprotected runners. Protected-owner fixes remain explicit below.

The original inventory has 228 grouped rows across 219 files. Eight additional, nonoverlapping predicate groups bring the audit total to 236: 12 `removed`, 163 `replaced`, 47 `kept-safety` and 14 `kept-another-listed-agent`. The 91-file command-line table overlaps those groups and is excluded from this total.

One grouped row combines related refusals or required inputs in one file; it does not count individual predicates or removed safety checks. Some candidates were ordinary data or ABI checks and remain required. Supplemental tables preserve required-input changes and findings absent from the original inventory.

Locations in the original tables refer to `6e082403`, including every embedded `L` reference in the recorded condition. File links open the current source; removed predicates no longer occupy those lines. Supplemental rows state their own line basis.

Actions have these meanings:

- `removed`: external process authority was deleted.
- `replaced`: a grouped condition now uses direct consumed inputs or an unused output directory; its concrete safety checks remain.
- `kept-safety`: a concrete input, protocol, resource, ABI or evidence-preservation condition remains.
- `kept-another-listed-agent`: the user assigned the file to another agent. The row states the retained safety or the required owner correction.

An image manifest linked into the executable defines consumed application regions and result capacity. A fixed native model catalogue defines the bytes its driver accepts. These inputs remain required. A separately reviewed image hash, historical host-source snapshot, queue-ready state or claim string does not establish current hardware state.

Runtime file inventories cover bytes uploaded to the device or parsed as direct safety inputs. Ancillary source copies, logs and unused manifest/template archives can change or disappear without denying launch. Object/header records remain necessary when a builder reuses compiled objects whose native layouts depend on those headers.

Consumed artifacts require the exact requested destination to be unused. Grants, plans, build outputs, generated inputs and launch bundles refuse an existing path; they never redirect into children that a later command might overlook. Evidence directories use unique timestamped children and preserve earlier results.

No standalone predicate requiring the final command line to equal an approved command was found at the base revision. The related path gates compared artifact inventories, queue prerequisites or separately reviewed inputs. No removed-process host C gate was found; the C candidates below validate native calls, files, geometry or results.

## Runtime safety remains required

Physical operations require the selected port’s `board_lock`, USB guard, current target/access checks and ROM/FEL sanity. The changed transport handlers retain their bounded exchanges and same-run upload/readback comparisons. These requirements do not qualify every historical standalone runner for execution.

Native session/build bindings, memory and DMA ownership, cache publication, shared clock/power coordination, supported clock/voltage limits, native thermal bounds and copied-result integrity remain required. Returning development runs require the host-armed watchdog and RTC breadcrumbs. Existing failure-stop and restoration handlers remain; process cleanup cannot establish physical recovery.

Storage writes retain the backup-first boot update with slot fallback, backed-up microSD data-partition confinement and the user-designated scratch-NVMe restriction. Removing review or queue records does not expand any write grant or target extent.
